\section{Background}
\label{sec:background}

This section introduces the concepts the rest of the report relies on, at the
level needed to follow the design decisions. Each concept is paired with the
role it plays in this project.

\subsection{Linked Open Data and the five-star model}

Linked Open Data (LOD) is the practice of publishing structured data on the web
under an open licence, using global identifiers and standard formats, and
linking it to data published by others. Tim Berners-Lee's five-star scale is a
compact way to describe the maturity of such a publication \cite{fivestar}.
Table~\ref{tab:five-star} maps each star to the artefact that earns it in this
project.

    \midrule

\subsection{RDF: triples, URIs and serialization}

RDF represents knowledge as triples: a subject, a predicate and an
object \cite{rdf11}. All triples in this report follow the pattern
\texttt{subject predicate object}; for example, the Negroni
(\texttt{.../id/cocktail/negroni}) \texttt{drink:baseSpirit}
\texttt{.../id/spirit/gin}. The predicate describes a relationship and may
point either to another entity (an object property) or to a literal value (a
datatype property).

Every entity is named by a URI (Uniform Resource Identifier),
a global name that looks like a URL but identifies a thing rather than a
page. This project mints its own identifiers under a single base
(\texttt{https://nathantrance.github.io/SemanticWeb/}) and adopts foreign
identifiers (Wikidata QIDs, DBpedia resource URIs) instead of re-minting
them. Global naming is what makes later linking (Section~\ref{sec:interlinking}) possible.

RDF is a data model, not a file format. The same triples can be written in
several syntaxes; converting between them changes nothing semantically. The
project keeps RDF/XML as the canonical syntax and generates the others on
demand (Table~\ref{tab:serializations}).

  \centering

    \toprule

\subsection{OWL 2: a richer schema}

RDF alone describes data; a schema for a domain is usually written in RDFS or
OWL. We use OWL~2 \cite{owl2}, which adds logical axioms beyond subclassing:
inverse properties (\texttt{owl:inverseOf}), sub-properties, and property
chains (\texttt{owl:propertyChainAxiom}) that let a reasoner derive new
triples. Section~\ref{sec:ontology} explains which axioms are used and why; the ontology itself
was edited in Prot\'eg\'e \cite{protege}.

\subsection{SPARQL and dereferenceable URIs}

SPARQL is the query language for RDF \cite{sparql11}. A \texttt{SELECT} query
returns rows, like SQL, and a \texttt{CONSTRUCT} query returns new RDF triples.
SPARQL 1.1 property paths (for example
\texttt{drink:usesIngredient/drink:ofIngredient}) traverse a chain of
properties in one expression; Section~\ref{sec:ontology} shows how this is used to execute the
ontology's property chain without a separate reasoner. A URI is
\emph{dereferenceable} when fetching it returns a representation of the thing
it names; serving RDF or HTML depending on the client's \texttt{Accept} header
is called content negotiation and is the strongest practical evidence for the
fourth star (Section~\ref{sec:query}).

\subsection{Source datasets}

Three external resources provide both the raw material and the linking targets:
TheCocktailDB, a community cocktail database with a free JSON API
\cite{cocktaildb}; Wikidata, a collaboratively edited knowledge base whose
items have stable QIDs and are published under CC0 \cite{wikidata}; and
DBpedia, which publishes structured content extracted from Wikipedia and is
linked to Wikidata through shared article titles \cite{dbpedia}. The exact
fields used, their licences and the collection procedure are described in the
next section.
